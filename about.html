將 AI 導入企業，而非將企業資料送出

許多企業評估導入 AI 時，面臨同一個問題： 對話與檔案最終會傳送到哪裡。 METRIC 的答案是：不傳送至任何外部位置，一律保存於企業自有的伺服器。

設計原則

五項不妥協的原則

  • 出廠預設不對外連線。對外連線須由管理員明確啟用；未經設定時，一律不連外。
  • 金鑰不下放。模型 API 金鑰僅存放於企業伺服器，不會出現在任何使用者電腦。
  • 僅安裝經原廠簽章的檔案。每份更新檔皆須通過原廠簽章驗證方可安裝；即使後台密碼外洩，亦無法藉此替換伺服器上的程式。
  • 不寫入企業帳號系統。串接企業帳號目錄時僅讀取、不寫入；停用使用者時，僅變更 METRIC 自身的資料。
  • 問題可直接定位。失敗原因直接顯示於畫面，無須另行翻查記錄檔。

系統組成

名稱部署位置職責
METRIC Portal企業伺服器 管理使用者、權限、模型與配額，統計用量，並負責派送新版本
METRIC Agent使用者電腦 使用者日常操作的應用程式：對話、檔案處理、知識庫查詢、例行工作排程、聊天機器人

授權檔由原廠直接提供，不在公開下載頁發佈。 授權檔規範席次數與到期日，並綁定貴企業的伺服器。

聯絡

聯絡方式

請於 GitHub Issues 建立 Issue，原廠將於該處回覆。
須具備 GitHub 帳號。Issue 內容為公開，請勿張貼授權檔、金鑰或企業內部位址。

開通、續約、增加席次及伺服器遷移，均透過同一窗口辦理。
